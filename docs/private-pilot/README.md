# PUBLICLY ACCESSIBLE PILOT — mainnet transactions
Baseline 200c6b9. Published separately under docs/private-pilot; docs/pilot recovery and homepage are unchanged. Self-contained index.html; config mirrored for review. No access control is implied by a scratch/private filename. Requires a trusted browser origin, Web Crypto and saved-owner wallet. Published with explicit authorization. The /private-pilot/ route is public, not private or access-controlled. Publication alone does not authorize any on-chain action.

Separate clicks: approve NFT #1 only, deposit, borrow chosen amount, approve exact repayment, repay, withdraw at zero debt. Approval for USDG never unlimited; existing insufficient nonzero allowance must be revoked first. All amounts parsed as bigint base units with up to six decimals. The separate funding request transfers exactly 0.000001 USDG (one base unit) to the vault using token.transfer; no approval is needed. It requires a connected owner, risk acknowledgement, explicit confirmation, runtime/chain/account/decimals/balance checks and successful eth_call; pending and receipt protections are shared. It is refused when the pool already has one base unit. ETH gas is extra; no lender share or automatic refund is created. Amount defaults blank. Risk checkbox and one-action confirmation required, followed by revalidation, eth_call and wallet prompt. No automatic transaction or next step. Receipt checks verify mined input/recipient/sender, canonical block and two confirmations before refresh. Ambiguous submission remains locked; inspect wallet before any retry. After page reload inspect wallet history: pending hashes are not persisted.

Current trial blocker: pool liquidity zero. Proposal only: 0.000001 USDG (one base unit) tests contract mechanics, not economic viability or wallet rounding; gas is extra. A selected amount needs at least that much existing pool liquidity. Do not deposit simply to test an unfunded pool. UI deliberately blocks NFT approval/deposit while trial borrowing prerequisites or liquidity are blocked. Repay and zero-debt withdrawal do not depend on borrow pause/freshness/liquidity, but USDG restrictions can prevent repayment. Physical custody, token freezes, upgrades and full browser/wallet behavior are not audited.
